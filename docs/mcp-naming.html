MCP tool naming

Canonical contract for every MCP plugin baked into the harness image — the ones under harness/mcp/<name>/ and any you add via harness/mcp.lock. The harness prefixes {server}__{tool}; this page is what goes on the right of the __. Plugins do not get a local dialect.

Why it matters: small models and the harness's closest-match repair pick tools by name tokens + description. Synonyms and double prefixes break matching, and a broken match is a serial round the Go loop could have batched.

Related: how a plugin gets into the image (custom-mcp.md); the eval that fails a fixture when a plugin renames a tool (eval_setup.md).

Layers (do not confuse them)

Layer Who owns it Example
MCP server id harness/mcp.lock name, mirrored in each agent's config.mcp strava, google, garmin
MCP tool name Binary registration activities_list, calendar_list_events
Host-facing name Harness joins with __ strava__activities_list 
{server_id}__{service}_{verb}_{object}[_{qualifier}]

Hard rules

  1. Tool = {service}_{verb}_{object…} Service first (resource / domain), then verb, then object. Same family as google-mcp (calendar_list_events, gmail_search_messages).

  2. Never put the server id in the tool name The harness already prefixes.

    • Bad: garmin_sleep_get → garmin__garmin_sleep_get
    • Bad: strava_get_activities → strava__strava_get_activities
    • Good: activities_list → strava__activities_list

  3. No dual aliases One name set per release. A breaking rename is a semver bump on the plugin, a mcp.lock bump, and the eval fixtures updated in the same PR — harness.yml runs the fixture well-formedness check and eval.yml fails the catalog drift before any model call.

  4. Stable verb set (prefer these; don't invent synonyms)

    Verb Meaning
    list Collection / page / day window
    get One resource by id
    search Query → hits
    create / update / delete Mutations
    format Pure reshape / hint (no side effects)

    Avoid verb-first tools (search_tracks, get_sleep) — rename to tracks_search / sleep_get style when touching that surface.

  5. Shared nouns across plugins when the concept is shared

    Concept Preferred service token Used by
    Calendar events calendar_ google
    Activities / workouts activities_ garmin, strava
    Saved Strava courses / share links routes_ / urls_ strava (urls_resolve; not maps__link_resolve)
    Devices (hardware) devices_ garmin
    Math expression_ / units_ math
    Web search web_ harness builtin web_search (not a plugin)
    Flight offers / dates / airports / returns / booking / quota offers_ / dates_ / airports_ / returns_ / booking_ / link_ / account_ flights
    Rental listings / rent estimate / markets / areas / quota listings_ / rent_ / markets_ / areas_ / link_ / account_ rentals
    Car listings / VIN / markets / quota listings_ / vin_ / markets_ / link_ / account_ cars (prefix disambiguates from rentals)
    Feed items / feed URL discovery items_ / source_ feeds
    X / Twitter public posts posts_ twitter (not tweets_)
    Places / Maps share links / leave-by place_ / link_ / route_ maps (place_search; link_resolve not short_url_*; route_eta is leave-by)
    Generated / edited pictures photo_ image (photo_generate / photo_edit; not image_* — double prefix)
    Chat face / wallpaper / room mood avatar_ / backdrop_ / theme_ chat (avatar_update, backdrop_update, theme_list; not chat_*, not pendant_*)

  6. Descriptions sell the intent First sentence = what the agent wants ("List recent Strava activities…", "Get last night's sleep…"). Nearest-name matching uses these tokens. Do not start with "Calls the Strava API v3 athlete/activities…"

  7. Args: snake_case task_list_id, video_id, time_min — never camelCase in schemas. Teach-in errors > silent defaults.

  8. Don't steal another plugin's domain words No calendar_* on fitness plugins for Google Calendar asks. No mail_* on Strava. A "calendar" of workouts is training_calendar_* (or excluded from the core tier).

  9. Lean catalogs Prefer --tool-tier core / presets / exclude so the published set stays small. Fat schemas starve local models even when names are perfect. Google ships about a hundred tools; the eval's manifest allowlists two.

  10. Tests lock names Every plugin asserts each registered tool matches ^[a-z]+_[a-z]+ and does not start with the server id string. That test runs under harness.yml and its coverage rolls into the harness badge.

Hyphenated server ids are fine; tool suffixes stay underscores. The harness aliases underscored prefixes (google_health__… → google-health__…) on call — suffixes are never rewritten. Web search is the unprefixed builtin web_search.

Checklist for a new or reshaped plugin

  • Pick a short server id (strava, not go-strava-mcp)
  • Every tool is {service}_{verb}_{object…} with no server-id prefix
  • Diff verbs/nouns against the table above before inventing a third synonym
  • Descriptions lead with agent intent
  • Args snake_case; hot paths documented in the tool description
  • Name assertion test; no dual registration
  • host-manifest prints; mcp.lock row added or bumped
  • Eval fixtures that name the tool updated in the same PR
  • Release notes include old→new map; bump semver on break
