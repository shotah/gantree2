Install — local, Cloudflare, or home

Same Worker, same wrangler.jsonc, three places it runs. Agents open zero inbound ports anywhere: the harness dials the Worker.

Place Command State Reach it at
Local dev npm run dev in-memory, .wrangler/ http://127.0.0.1:3000
Cloudflare wrangler deploy (CI) Workers · DO · KV · R2 · Containers your workers.dev or custom domain
Home (Mini / NUC / VM) npm run deploy:home (celld deploy) celld's SQLite + an S3-compatible bucket you own Tailscale HTTPS or a Cloudflare Tunnel

Need Node 22 (node -v). Distro apt install npm is often Node 20 and will fail.

Google OAuth client

gantree does not create this. GCP → APIs & Services → Credentials → Create credentials → OAuth client ID.

Field Value
Application type Web application
Authorized redirect URIs one line per place you run, below
Scopes (consent screen) openid, email, profile — nothing else
Place Redirect URI
Local dev http://127.0.0.1:3000/api/auth/callback/google (Google accepts loopback http)
Cloudflare https://<worker-origin>/api/auth/callback/google
Home https://<mini>.<tailnet>.ts.net/api/auth/callback/google or your Tunnel hostname

Google rejects private LAN IPs (http://192.168.x.x). A home box must sit behind Tailscale HTTPS or a Tunnel for sign-in to work. One client can carry all three redirects.

Consent screen: External (or Internal if Workspace-only). External + Testing → add yourself as a test user.

Local dev

git clone https://github.com/shotah/gantree2.git
cd gantree2
cp .dev.vars.example .dev.vars
# .dev.vars: GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, SESSION_SECRET (≥32 chars),
#            GANTREE_ADMINS=you@example.com
npm ci
npm run dev            # http://127.0.0.1:3000 → /login

Sign in. You are admin. A second Google account gets not_allowed until you add it on /users.

Without a Google client: GANTREE_DEV_USER=118212345678901234567:you@example.com in .dev.vars fakes a session on loopback only. The sub is 10–32 digits. It still has to be in GANTREE_ADMINS or GANTREE_ALLOW. Details: access.md.

npm run dev is Vite on 127.0.0.1:3000. It serves the Durable Objects. Containers need Docker, which local dev does not assume: wrangler.jsonc sets dev.enable_containers to false, and the agent page shows the container as unknown instead of failing. Screenshots in this repo were taken against npm run dev. npm run build && npm run start is the built Worker under Miniflare (dist/server/wrangler.json); use it when you want the production bundle, not to get Durable Objects.

npm run seed   # dev must already be up. Fills Kit and Ada through the HTTP API.
npm run shot   # headless Chrome → assets/docs/*.png. CHROME_BIN overrides the Chrome path.

npm run seed writes any missing GANTREE_DEV_USER or AGENT_BEARERS into .dev.vars and then tells you to restart dev so the Worker reloads them. npm run shot opens /chat as the loopback dev user. A member picker needs that variable unset and GANTREE_SHOT_AS_MEMBER=1 (seed writes the member cookie).

Cloudflare

CI does it. Repository → Settings → Secrets and variables → Actions:

Kind Name Value
Variable GOOGLE_CLIENT_ID from GCP
Variable GANTREE_ADMINS you@example.com (grammar: access.md)
Variable GANTREE_ALLOW optional members
Secret GOOGLE_CLIENT_SECRET from GCP
Secret SESSION_SECRET openssl rand -base64 48
Secret CLOUDFLARE_API_TOKEN Workers Scripts Edit · Workers KV Storage Edit · Workers R2 Storage Edit · Account Settings Read
Secret CLOUDFLARE_ACCOUNT_ID dashboard sidebar

Push to main. ci.yml runs tests, lint, typecheck, build. deploy-cloudflare.yml then runs wrangler deploy --var … and wrangler secret bulk. It fails fast if any of the four auth values is empty. Add the Worker origin to the Google client's redirect list.

By hand from a laptop (same token in your shell):

npm run deploy
npx wrangler secret bulk < secrets.json   # {"GOOGLE_CLIENT_SECRET":"…","SESSION_SECRET":"…"}

The Worker itself runs on the free tier. Containers need Workers Paid — see below.

Containers

One harness container per agent. The Cloudflare account needs Containers enabled (Workers Paid). wrangler deploy builds harness/Dockerfile (context is the harness/ directory, which is where that file's COPY expects to run) and ships the image with the Worker. wrangler.jsonc names the application gantree-harness, class Harness, five instances, plus a v2 migration for the Harness Durable Object.

The process env is the dial-back. Everything else (LLM keys, mcp.toml, persona) arrives on the socket in a config frame.

Var Value
CHANNEL pendant
PENDANT_MAILBOX_URL wss://<origin>/ws/<slug> — the harness adds ?role=crane
PENDANT_BEARER room bearer from the Agent DO
SNAPSHOT true
SNAPSHOT_INTERVAL 5m

Set PUBLIC_ORIGIN to https://<worker-origin> (no path) when the host the harness should dial is not the browser's. Leave it unset locally and start uses the request origin.

The image does not EXPOSE a port. The supervisor still sets defaultPort 8080 so the Container class has a probe port; gantry dials out and does not listen.

Local wrangler dev without Docker has no container binding. GET /api/agents/:slug/container then returns state: "unknown".

The gantry binary in this tree also refuses to stay up without PENDANT_ALLOWED_USERS. The start body does not carry that list — the room lives on the Agent DO — so a real container exits until the harness takes the room from the config frame.

Home (celld)

celld runs the Workers platform on your own box from the same wrangler.jsonc: Workers, Durable Objects, KV, R2, Cron, static assets, and — experimentally — Containers. Install per its README; it needs Docker or Podman for the harness container and an S3-compatible bucket (MinIO on the same box is fine) for durable state. celld dev needs neither.

# on the Mini
cat > /etc/gantree/vars.env <<'EOF'
GOOGLE_CLIENT_ID=…
GOOGLE_CLIENT_SECRET=…
SESSION_SECRET=…
GANTREE_ADMINS=you@example.com
GANTREE_ALLOW=
EOF
chmod 600 /etc/gantree/vars.env

git clone https://github.com/shotah/gantree2.git /opt/gantree
cd /opt/gantree && npm ci
CELLD_VARS_FILE=/etc/gantree/vars.env npm run deploy:home

Put a hostname in front:

Tailscale (preferred): tailscale serve --bg https / http://127.0.0.1:<celld-port>. Redirect URI is https://<mini>.<tailnet>.ts.net/api/auth/callback/google.

Cloudflare Tunnel (zone already on Cloudflare, no WAN ports): cloudflared tunnel run with the public hostname → http://127.0.0.1:<celld-port>.

Do not open a router or cloud firewall port to the world. celld stops on any wrangler.jsonc key it does not model, so a manifest that deploys to Cloudflare deploys here, or tells you exactly why not.

Home deploy is not a GitHub Action. GitHub cannot reach the Mini and should not.

Harness image

Agents run ghcr.io/shotah/gantree-harness:<tag> — the Go harness plus every MCP server in harness/mcp.lock baked into /opt/mcp. harness-image.yml builds it when harness/** changes, smokes gantry version, and on main pushes ghcr.io/shotah/gantree-harness:<sha>. wrangler deploy builds the same Dockerfile into the account's container registry. Recreate picks up a newly deployed image.

Build it yourself with any Docker-API engine: cd harness && docker build -t gantree-harness:local . (~70 s warm). Rootless podman is enough — systemctl --user enable --now podman.socket and DOCKER_HOST=unix:///run/user/$UID/podman/podman.sock make the docker CLI talk to it; no daemon, no root. Smoke: docker run --rm gantree-harness:local version.

Release

npm test
npm run release:dry          # show next tag
npm run release              # patch bump, tag v*, push
npm run release -- --bump=minor

Requires a clean tree. Tags trigger release.yml (GitHub release) and harness-image.yml (tagged image).
